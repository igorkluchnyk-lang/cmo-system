# Операційний шар: як керувати командою агентів

> Джерела: вебінар «AI-агенти для маркетингових команд» (Octocrew.ai + OSMO, 15.09.2026 — Аліна Уварова,
> Олексій Никитін, Ярослав), статті Аліни на telegra.ph (05–09.2026), канал @alinarunsagents.
> Це закриває модуль «Керування командою», якого в курсі «Маркетологія» немає — тільки команда тут з агентів.

## Копілот ≠ агент

| | Копілот (асистент) | Агент |
|---|---|---|
| Хто ініціює | ти просиш — він робить | тригер або розклад |
| Пам'ять | сесія | постійна, сам оновлює |
| Середовище | твій комп'ютер | своє (VPS, бот) |
| Результат | відповідь у чаті | дія в системі + звіт |
| Керування | штовхаєш щоразу | критерії запуску + кнопка «стоп» |

**`/cmo` — копілот.** Це правильно: судження, стратегія, гейти лишаються з людиною.
**Виконавчий шар має бути агентами** — те, що об'ємне, повторюване, за розкладом, потребує виконання, а не продумування.
Не плутати: не робити з `/cmo` автономного агента, і не тримати виконання в копілоті.

## Scorecard: 6 питань перед тим, як віддати процес агенту

1. **Тригер.** Коли і чому запускається? Не «щопонеділка о 9», а точна умова — може бути нелінійною (стаття вийшла → реакція → інший канал).
2. **Результат.** Що конкретно має існувати після відпрацювання? Найважливіше питання. Нові моделі виконують краще, коли ціль чітка — усе інше менш важливе.
3. **Ризик.** Що найгірше станеться, якщо агент помилиться? Це визначає рівень автономії.
4. **Контекст.** Які правила й матеріали потрібні, хто їх оновлює, де живуть? Системи самі не запам'ятовують — треба окремий механізм.
5. **Інтеграції.** Через що діє? MCP або API з документацією. Браузер — останній варіант: довго, ламко.
6. **Роль людини.** Хто приймає результат і вирішує, чи продовжувати?

Без чіткої відповіді на 2 і 6 — не автоматизувати. «Займайся SEO» → garbage in, garbage out.

## Earned autonomy: три рівні, які треба заслужити

```
draft-only  →  approval-gated  →  bounded autonomy
агент готує     агент має інструмент   агент робить сам
ти публікуєш    для дії, але показує   у визначених межах
                картку: approve /
                decline / edit
```

**Правило переходу:** N карток поспіль без правок → наступний рівень. Октокрю називає 50 із 50.
Різні процеси стартують з різних рівнів — залежить від ризику з пункту 3. Реклама з бюджетом — ніколи не з автономії.

Інтерфейс майбутнього — стрічка карток-рішень у месенджері. Керівник не робить, а приймає.

## З чого починати: те, що не шкодить

Безпечні перші агенти — **досліджують, драфтять, рекомендують. Не діють.**
Огляд конкурентів · моніторинг цін · техаудит сайту · моніторинг коментарів і відгуків · дайджест рекламного кабінету (CPL, CTR, вигорання аудиторії, перерозподіл бюджету).
Зрозумілий результат, простий контекст, перевірка нічого не ламає, можна щодня.

Найпростіший старт: у проєкті з найбільшим контекстом спитати «дай 3–5 прикладів корисного, що ти міг би готувати щодня».

## Цикл агента і performance loop

Команда → контекст → план → виконання → **перевірка** (сам або інший агент) → результат людині.

- **Кожен агент логує дії.** Раз на тиждень оркестратор читає логи й коригує. Без логів немає performance review.
- **Що не вимірюється — не покращується.** Критерій готовності задається до запуску; через нього і покращується система.
- **Self-improving loop — обережно.** Агент, який оптимізується під охоплення, за кілька ітерацій випливе за межі брендбуку. Дрейф компаундиться в дрібницях. Правило: зміни в скіли/персону проходять другого агента або людину, і перевіряються тестами. Метрика оптимізації — з юніт-економіки, не з vanity.
- **Скафолдинг = донавчання.** Після розгортання агента ти все одно ведеш його як нового співробітника: дивишся результат, вказуєш, чого не врахував.

## Що робить агента production-ready (≈2 тижні)

Роль → контекст → **приклади хорошого і поганого результату** → identity → інструменти → тест на реальних задачах → відлов дивної поведінки → правки → performance loop.
Найдовше — зрозуміти, що саме треба і як виглядає «добре». Замість найму — промптинг, замість онбордингу — identity-файл, замість 1:1 — логи.

## Моделі: ролі різні — моделі різні

- Стратегія й судження — найсильніша модель, навіть якщо вона «перепитує» на простому.
- Щоденний контент — модель, яка краще пише в межах голосу; дивись не рейтинг, а скільки довелось переписати.
- Скриптовані прості задачі — дешева модель.
- Багатослівна модель → жорсткі ліміти обсягу в інструкції.
- **Короткі задачі ≠ прості.** Помилка роутингу.
- Змінюй **один фактор за раз**: модель, або reasoning, або інструкцію. Інакше не зрозумієш, що спрацювало.
- «Працює — не чіпай.» Нова модель ≠ причина міграції: перегляд інструкцій коштує часу.

## Правила, які економлять гроші й нерви

- **«Готово» ≠ зроблено.** Tool call повертає «ок» — це не доказ. Проси посилання/шлях/дифф на результат. (Наш власний випадок 21.08: скрипт синхронізації відрапортував успіх, а правка не доїхала.)
- **Один тригер → багато форматів.** Фіча в changelog → стаття → newsletter → адаптація під 5 соцмереж. Людина: 0 кроків.
- **Інструмент без MCP/API і документації — не автоматизується.** Обирай стек за цим критерієм. Агентські шлюзи: Composio (універсальний MCP), Zernio/Postiz (постинг, реклама, месенджери — беруть максимум із офіційних API).
- **Візуали = генерація + HTML-шар.** Генерувати тільки те, що не робить HTML (фон, продукт), текст і сітку накладати по дизайн-системі — так не галюцинують слова, працює нескінченно по шаблону. Агент показує превʼю обрізки під Instagram.
- **Описати процес — через інтерв'ю.** «Опитай мене, як я роблю цю задачу покроково» → агент робить припущення, ти кажеш так/ні → драфт. Потім — скіл для опису процесів, щоб результат був повторюваним.
- **Скіл для написання скілів.** Вийшов класний результат у сесії → запакувати одразу, інакше загубиться. Правки наслаюються на скіл, не переробляються.
- **Секрети** — Yopass / OneTimeSecret / PrivateBin. Логін і пароль ніколи в одному повідомленні.
- **Якщо агент палить токени** — спитай його «чому», часто конфліктні інструкції або дублювання. Один випадок: −80% витрат після одного питання.
- Порядок вартості: inference $100–200/міс на команду з агентами, сервер $50–100, шлюзи-конектори окремо.

## Що з цього НЕ брати

- Заявлені результати (×2 трафік, CPL ÷2) — n=1, без періоду й контролю. Закон №12: не цитувати як факт.
- Платформу (OpenClaw, Octocrew harness) — рішення не в платформі, а в описаних процесах і гейтах.
- Оптимізацію під охоплення — суперечить головному принципу системи.
- Твердження «Claude погано пише українською, тому Codex» — думка одного спікера; наш ToV-шар працює, перевіряється правками, не рейтингом.
